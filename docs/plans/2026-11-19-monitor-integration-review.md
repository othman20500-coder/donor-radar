# مراجعة تكامل الرصد مع منظومة رادار المانحين

مراجعة للكود المحلي لنسخة تطوير Cloudflare بتاريخ 19 نوفمبر 2026. لم تتضمن تعديل التشغيل أو تفعيل الجدولة. النتائج تخص هذه النسخة؛ لم يُفحص كود الإنتاج الحي.

## النتيجة

مركز الرصد يشترك مع المنصة في المصادقة وقاعدة البيانات والنسخ الاحتياطية، لكن دورة الفرص والأدلة والتنبيهات منفصلة عن دورة العمل الرئيسية. تفعيل مؤقت للرصد وحده لن يجعل الفرص المكتشفة تظهر في لوحة القرار أو تتصل بالمشاريع والتقديم.

## الأدلة الحالية والفجوات

| المكوّن | الموجود | الفجوة |
|---|---|---|
| دليل الجهات | بيانات الجهات وتعديلاتها، مع الموقع والبوابة والمجالات | جدول مصادر الرصد لا يحمل donor_id؛ يلزم ربط المصدر بمعرّف الجهة |
| الفرص التمويلية | الواجهة تعرض DATA.calls؛ متابعة كل فرصة في cw_ | جدول opportunities منفصل؛ الاعتماد يغيّر review_status فقط ولا ينشئ فرصة في الواجهة الرئيسية |
| حفظ الفرص | validator يسمح بمعرّفات فرص catalog الحالية فقط | إدخال فرصة مكتشفة يحتاج نموذج فرص ديناميكي والتحقق منه في الخادم، وليس تعديل الواجهة وحدها |
| الأدلة | أدلة على مستوى المصدر ومحتواه | لا علاقة evidence_id/ opportunity_id؛ قبول دليل لا ينقل تاريخًا إلى الفرصة |
| المطابقة | matchD يطابق المشروع بالجهة اعتمادًا على المجالات وتقييم الجهة؛ API monitor/match يقارن قوائم مرسلة إليه | طريقتان مختلفتان، والثانية لا تقرأ المشروعات أو تحفظ الترشيحات ولا تظهر في واجهة المركز |
| المشاريع والتقديم | proj_ لكل مشروع يحفظ جهة واحدة ومرحلة ومسؤولًا وخطوة وموعدًا | لا opportunity_id، ولا سجل طلب مستقل لكل مشروع وفرصة؛ يلزم منع ضياع متابعة طلب سابق عند إضافة طلب آخر |
| التنبيهات | تنبيهات رئيسية من DATA.calls والوثائق والمتابعات؛ مركز الرصد له alerts | لا تغذية موحدة؛ تحديث الرصد لا يرفع مراجعة الحالة المشتركة المستخدمة في تحديث الواجهة |
| المصادر | الصفحة الرئيسية sourceFilesCatalog تعرض مرفقات المشاريع ووثائق الجمعية | ليست قائمة مواقع الرصد؛ العدد الظاهر فيها لا يساوي عدد مصادر الفحص |
| الأدوار | الرصد محصور بالمدير؛ المحرر يتابع السجلات المسموحة | يجب تعريف صلاحيات المراجعة والنشر وإسناد العمل بوضوح |
| النسخ | snapshot تشمل records وجداول الرصد والحسابات وسجل التدقيق | الارتباط موجود ويجب توسيعه بأي جداول جديدة واختبار استعادتها |
| التشغيل الدوري | لا scheduled handler أو cron؛ الفحص الحالي يدوي ويتحقق من جلسة المدير | يحتاج منفذًا آليًا بصلاحية نظام محدودة وتدقيق واضح، مستقلًا عن جلسة المستخدم |

## المسار المقترح للتكامل

1. الجهة في الدليل لها مصادر مراقبة محددة وروابط سياسات ومواعيد مراجعة.
2. عامل دوري مستقل يفحص المصادر المسموحة ويكتشف روابط الإعلانات؛ قراءة تفاصيل الرابط تتطلب تحققًا من السماح أيضًا.
3. يُنشئ إعلانًا مرشحًا بمعرّف ثابت ورابط موحد، ويحتفظ بالدليل لكل حقل وتاريخ الاستخراج. يمنع التكرار ويحتفظ بتاريخ التغييرات.
4. يراجع المسؤول الأهلية والمواعيد والمبلغ والمجال. اعتماد الدليل منفصل عن اعتماد الفرصة وقرار التقديم.
5. اعتماد الفرصة يتيحها في قائمة الفرص الرئيسية وعداداتها والبحث والتقويم، عبر مصدر بيانات مشترك.
6. تُطابق الفرصة مع المشروعات النشطة وفق شروط الأهلية أولًا ثم المجالات والفئة والمنطقة والمبلغ والجاهزية. المعلومة المجهولة تظهر كمجهولة، ولا تتحول إلى عدم أهلية مؤكد. تُعرض أسباب الترشيح والفجوات.
7. يختار الموظف «بدء التقييم» لمشروع وفرصة؛ ينشأ طلب مستقل يربط المشروع والفرصة والجهة والمسؤول والمرحلة والموعد والخطوة التالية.
8. يتغذى مسار التقديم ومهامي والتواصل والنتائج من الطلب نفسه. لا يُسجل «قُدم» أو «قُبل» بسبب اكتشاف الإعلان آليًا.
9. تنبيهات اللوحة تجمع الجديد وتغير المواعيد وفشل الفحص والمهام، مع منع التكرار وروابط إلى السجل المعني.
10. لا يُحسب الإعلان المرصود أو ترشيح المطابقة تمويلًا مضمونًا؛ يبقى الاعتماد المالي مرتبطًا بقرار موثق وصلاحيات المدير.

## ترتيب التنفيذ المقترح

- أولًا: توحيد معرّفات الجهات والفرص وربط الأدلة، ثم نشر الفرصة المعتمدة في الواجهة الحالية واختبار الحالة المشتركة.
- ثانيًا: إضافة تشغيل دوري محدود ومراقبة الصحة والتوقف وإعادة المحاولة واحترام السياسات، مع مصادر رسمية مناسبة للجمعية.
- ثالثًا: دمج المطابقة وتوضيح أسبابها، وإنشاء طلبات التقديم المستقلة وإسنادها وربط التنبيهات.
- رابعًا: اختبار كامل من إعلان جديد إلى اعتماده وترشيح مشروع وإسناد طلب وتغير الموعد، ثم اختبار الصلاحيات والنسخ والاستعادة.

## معايير قبول التكامل

إعلان جديد في مصدر اختبار ينتج مرشحًا واحدًا؛ لا يظهر كمعتمد قبل المراجعة. بعد الاعتماد يظهر في الفرص والبحث والعدادات. يرتبط كل تاريخ بدليله الصحيح. ترشيح المشروع له تفسير. بدء التقييم ينشئ طلبًا دون استبدال طلب سابق. تغيير موعد يظهر تنبيهًا ولا يغيّر تاريخًا معتمدًا بصمت. الفحص الدوري يعمل دون جلسة مدير. سحب سياسة المصدر يمنع طلباته التالية. لا يُضاف مبلغ إلى التمويل المعتمد دون قرار بشري مخوّل.

## مواضع الاستدلال في الكود

- cloudflare/monitor.mjs: recordPage وmonitorRoute، خصوصًا review وevidence وmatch.
- cloudflare/migrations/0001.sql: جداول sources وopportunities وevidence والتنبيهات.
- cloudflare/store.mjs: state وatomic؛ الحالة المشتركة تُحمّل records.
- server/validation.js: createValidator، cw وproj، والتحقق من معرّفات catalog.
- source/base-v9.html: matchD (1232)، renderAlerts (1331)، finPipeline (1365)، callDonor (1713)، callInfo (1719)، callRows (1772)، uiSearchItems (2533)، sourceFilesCatalog (2671).

- cloudflare/backup.mjs: snapshotTables.
